# CLAUDE.md

This file provides guidance to coding agents when working with code in this repository.

## Project Overview

Yoink is a Solidity smart contract project for minting custom NFT tokens with modifiable metadata. The contract is unaudited and intended for educational/personal use.

**WARNING**: This contract is unaudited. Users assume all responsibility when using it.

## Development Commands

### Installation
```bash
yarn install
```

### Build & Compilation
```bash
yarn compile          # Compile contracts with TypeScript transpilation
yarn clean            # Clean build artifacts
yarn typechain        # Generate TypeScript bindings for contracts
```

### Testing
```bash
yarn test             # Run tests with auto-reload on file changes (uses nodemon)
yarn coverage         # Run test coverage analysis with solidity-coverage
```

The test suite uses Hardhat, Mocha, and Chai. Tests automatically recompile and rerun when `.ts` or `.sol` files change.

### Linting & Formatting
```bash
yarn lint             # Run all linters (Solidity, TypeScript, and Prettier check)
yarn lint:sol         # Lint Solidity contracts with Solhint
yarn lint:ts          # Lint TypeScript files with ESLint
yarn prettier         # Format all files
yarn prettier:check   # Check formatting without modifying files
```

### Deployment
```bash
yarn deploy-local     # Deploy to local Hardhat network
yarn deploy-rinkeby   # Deploy to Rinkeby testnet
yarn deploy-mainnet   # Deploy to Ethereum mainnet (uses Frame for hardware wallet support)
yarn verify           # Verify contract on Etherscan after deployment
```

### Local Development
```bash
yarn server           # Start local Hardhat node
yarn start            # Run the main script (scripts/run.ts)
```

### Static Analysis
For Slither (Python-based security analyzer):
```bash
pipenv shell          # Enter Python virtual environment
pipenv install        # Install Python dependencies
slither .             # Run Slither analysis
```

## Environment Configuration

Copy `.env.example` to `.env` and configure:

- `MAINNET_APP_SECRET_KEY` - Alchemy/Infura API key for mainnet
- `RINKEBY_APP_SECRET_KEY` - Alchemy/Infura API key for Rinkeby
- `MAINNET_WALLET_PRIVATE_KEY` - Wallet private key (mainnet uses Frame)
- `RINKEBY_WALLET_PRIVATE_KEY` - Wallet private key for Rinkeby
- `ETHERSCAN_API_KEY` - For contract verification
- `REPORT_GAS` - Enable gas reporting in tests (boolean)
- `COIN_MARKET_CAP_API_KEY` - For USD gas cost estimates

## Architecture

### Contract Structure

**Main Contract**: `contracts/Yoink.sol`
- Inherits from OpenZeppelin's `Ownable` and `ERC721URIStorage`
- Implements custom NFT minting with either:
  - Dynamic metadata via URI (external JSON file)
  - Static metadata via onchain base64-encoded JSON
- Function overloading for `mintNFT()` and `updateTokenURI()` methods

**Library**: `contracts/libraries/Base64.sol`
- Base64 encoding utility for onchain metadata storage

### Key Contract Features

1. **Minting Fee System**: Configurable minting fee with address exemptions
2. **Metadata Flexibility**: Supports both URL-based and onchain metadata following OpenSea standards
3. **Owner Controls**:
   - Update minting fee
   - Toggle address exemptions
   - Withdraw accumulated fees
4. **Token Ownership**: Only token owners can update their token's metadata

### Deployment Architecture

**Mainnet**: Uses Frame (hardware wallet integration via eth-provider)
- Configured in `scripts/deploy-mainnet.ts`
- Requires Frame desktop application running
- Supports hardware wallets for secure deployment

**Testnet/Local**: Standard Hardhat deployment
- Configured in `scripts/deploy-testnet.ts`
- Uses private key from environment variables

### Scripts Organization

- `scripts/deploy-mainnet.ts` - Mainnet deployment with Frame integration
- `scripts/deploy-testnet.ts` - Testnet/local deployment
- `scripts/verification.ts` - Etherscan contract verification template
- `scripts/run.ts` - Development testing script

### Network Configuration

Networks are configured in `hardhat.config.ts`:
- **mainnet**: ChainID 1, URL from `MAINNET_APP_SECRET_KEY`, uses Frame
- **rinkeby**: ChainID 4, URL from `RINKEBY_APP_SECRET_KEY`, uses private key
- **localhost**: Default Hardhat network for local development

### Testing Structure

Tests in `test/Yoink.test.ts` use:
- Hardhat's ethers integration
- Waffle matchers for Solidity assertions
- TypeScript types generated by Typechain
- Multiple signers (account1-5) for multi-account scenarios

Gas reporting is enabled via `hardhat-gas-reporter` when `REPORT_GAS=true`.

## NFT Metadata Standards

Token metadata must follow OpenSea's schema:

```typescript
{
  "description": string,
  "image": string (URL),
  "name": string,
  "attributes": [
    {
      "trait_type": string,
      "value": string
    }
  ]
}
```

The contract supports both:
1. **URI-based**: Pass a URL to hosted JSON metadata
2. **Onchain**: Pass a `TokenMetadata` struct that gets base64-encoded and stored onchain

## Important Notes

- Before deploying, update placeholder values in deployment scripts (name, symbol, mintingFee, firstTokenMetadataURI, exemptAddresses)
- The constructor automatically mints token #1 to the deployer with the provided metadata URI
- Token IDs start at 1 (not 0) and increment sequentially
- Contract events use past tense naming: `MintedToken`, `UpdatedTokenURI`, `AddressExemptionChanged`
